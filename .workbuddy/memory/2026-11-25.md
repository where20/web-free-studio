## 即梦 429 限流 & 状态判定三连修（16:20 · commit 388f88e）

- **现象**：用户看到「伺服器忙碌中，請稍後再試」= 上游 `{code:10001, message:"The server is busy. Please try again later.", detail:"... llm gateway HTTP 429"}`。
- **根因**：同一 `agent_thread_id` 并发提交 3 条（旧 15s + 2×14s）→ 即梦 agent 的 **LLM 网关 429 限流**。`DREAMINA.maxActive` 默认 2→**1（串行）**。
- **暴露的三个判定 bug（都修了）**：
  1. `run.state=4` 未映射 + `fail_reason` 是**对象** → `/fail/i.test(obj)` 恒 false → 任务永远「生成中」（实测装了 50 分钟）。
  2. `fail_reason` 对象直传前端 → 渲染成 `[object Object]`。新增 `normalizeFailReason()` 归一化成中文（429/busy → 「上游繁忙（即梦 agent 的 LLM 网关限流 429）…建议一次只跑 1 条」）。
  3. `state=3` 只代表 run 结束，**不代表成功**：有「state=3 + 有 artifact_id + 文案写着视频生成失败」的组合 → 贴成 done 后 3 次拿不到产物直链，卡「已完成但没有视频」僵尸行。现在 state=3 且文案含失败/429 → failed；另加「done 但 3 次无产物直链 → 收口判 failed 并退还额度」。
- `STATE_LABEL` 补 `4: "生成失败"`；前端任务卡新增 `.failmsg` 直接显示失败原因（原来只亮一个「失败」badge，用户只能来问）。
- 串行重拍脚本 `scripts/serial-tour-2seg.sh`：冷却 N 秒 → 段1 提交并等出片 → 段2 提交并等出片 → ffmpeg concat。提交失败（429）自动退避重试 3 次。
- 单测 82/82。
