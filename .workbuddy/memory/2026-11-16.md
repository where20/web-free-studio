# 2026-11-16 · web-free-studio（PabaTV 本地落地）

## 做了什么

把 `www.paba.tv/#video` 的视频生成能力落成本机服务，产出 REA 报告 + 可运行代码。

### 核心技术结论（复用价值高）

1. **PabaTV 是 Cookie 鉴权**：`h3v`（身份，1 年）、`h3s`（会话，3 天）、`__Host-h3d`（设备）。无 CSRF、无签名头。
2. **写接口靠 TLS 指纹拦非浏览器**：同 Cookie 下 `curl`（含完整浏览器头）→ `403 challenge_required`，浏览器页内 `fetch` → `200`。
   → 任何「纯 Node/curl 代理」方案在写侧必然失败，必须走真实浏览器执行器。
3. **读口也会被一起拦**：触发一次挑战后 `/auth/me`、`/v1/videos` 全 403，需重新过 Turnstile。
4. **挑战流程**：`POST /v1/videos/generations` → 403 `challenge_required` → iframe `/__h3c/fresh.html`（Turnstile sitekey `0x4AAAAAAFqqk90sgLbzMVhY`）→ `POST /__h3c/verify {token}` 换 Cookie → 重发原请求。
5. **产物回流不需鉴权**：`/v1/videos/{id}/content` 带 Cookie → 302 到 `media.paba.tv`（公开 CDN，支持 Range），纯 HTTP 即可镜像。
6. **提交体**：`{channel_id, model, model_v:2, prompt, duration, resolution, aspect_ratio, tier?, style?, seed?, reference_images?, first_frame?}` + 头 `Idempotency-Key`；重复提交 `409 duplicate_submission`。
7. **免费额度**：`minimax-h3-flash` 768p 全时长 0 元，每天 15 条/账号；免费队列排队 10+ 位，成片 10–40 分钟。

### 代码结构

`server/src/{config,store,cdp,chrome,lane,sync,api,events}.mjs` + `web/index.html` + `server/cli.mjs`。
零依赖（Node 22 全局 fetch/WebSocket）。双执行后端：`ChromeLane`（每账号独立 `--user-data-dir`）/ `EgoLane`（ego-browser taskSpace）。

### 本机环境坑

- **WorkBuddy 沙箱内 spawn Chrome 必崩**（renderer/GPU/network service crash），`--no-sandbox` 也无效。
  沙箱里只能用 `EgoLane`（ego-browser 由宿主启动，不受沙箱限制）；`ChromeLane` 需在普通终端验证。
- **ego-browser 的 `console.log` 走 stderr**，不是 stdout —— 用它取返回值要两路一起抓。
- `ego-browser --ego-server-name=xxx` 在沙箱里连不上 bootstrap（需 Full Access）。

## 追加（16:10 新增账号入口）

- 入口提到**顶栏「＋ 新增账号」**，弹窗三条路径：浏览器登录 / 导入 Cookie / 接管 ego 会话。
- **登录接口改非阻塞**：立即返回 `{phase:"awaiting_user"}`，后台轮询到 online 再同步。之前阻塞等待 300s 导致请求挂死（实测 60s 无响应）。
- **ego 后端只能接管 1 个账号**（单浏览器 profile），第 2 个必须用浏览器登录或导入 Cookie；后端已加校验（400）。
- `syncAll` 跳过 `new/removed/disabled` 账号；登录失败不再复活已删除槽位。
- Chrome 启动：`--headless=new` 在沙箱里秒崩，已加**失败自动降级有头**；实测即便有头也会在加载页面后数秒被沙箱杀掉 —— 本环境只有 ego 稳定。
- 经验：`waitForChrome` 的 fetch 无超时，必须与「进程退出」竞速，否则请求悬挂。

## 追加（16:45 删除与授权修复）

### 修的问题

1. **账号删不掉**：UI 只有 选用/同步/授权/停用，没有删除。已加「删除」按钮（软删 + 停用 + 停浏览器），API 支持 `{"purge":true}` 连 profile 一起删。
2. **授权窗口"没打开"**：`Page.open(port, url)` 只建标签页不保证加载，也不置前。改为显式 `goto` 校验 + `Page.bringToFront` + macOS `open -a "Google Chrome"`；页面连不上就 4 次探测后立刻报错，并把 UI 自动切到「导入 Cookie」页（新增「打开登录页」按钮，用系统浏览器兜底）。

### 顺带修掉的坑

- **ego 调用可能永不返回**（CLI 忽略 SIGTERM）→ execFile 的 timeout 不生效，把车道锁死。已加 `Promise.race` 硬超时 + SIGKILL。
- **页内 fetch 无超时** → evaluate 挂死。已加 AbortController 25s（下载另给 600s）。
- **同步串行锁**：调度器与手动同步并发操作同一 ego 标签页会互相卡死 → `withSyncLock` + 150s 看门狗。
- **镜像下载拖垮同步**：免费档 CDN 实测有 3KB/s 的情况（1.9MB 要 10 分钟）→ 改后台队列（并发 1），失败 3 次后 30 分钟退避。
- **多实例会互相覆盖 db.json**：启动加 EADDRINUSE 保护。

### 验证

同步 1.4–1.7s（之前 100s+ 超时）；3 条成片全部落本地（14.5MB）；删除接口 200；登录接口 12ms 返回。

## 追加（17:05 免浏览器接入 + 账号编辑）

### 关键突破：ego 的 `page.cdp()` 可用

- `page.cdp("Network.getAllCookies")` / `setCookie` / `deleteCookies` 都能用 → **可以直接读写 httpOnly cookie**。
- 由此实现「一浏览器托管多账号」：每账号一份 cookie 罐（`data/accounts/<id>.cookies.json`，0600），每次调用前按账号注入，用完保持隔离。
- 不再依赖 Chrome 启动 —— 这正是沙箱里唯一可行的多账号路径。

### 新增能力

| 能力 | 实现 |
|------|------|
| 粘贴 Cookie 接入 | `POST /api/accounts/:id/cookies` → 落盘 + `/auth/me` 校验 + 接管 |
| 邮箱密码登录 | `POST /api/accounts/:id/login-password` → 车道内调 `/auth/account/login`，成功后自动存 cookie；错误密码返回 401「邮箱或密码不对」 |
| 账号编辑 | `GET /api/accounts/:id/detail` + `POST /api/accounts/:id/update`（备注/后端/停用）；UI 弹窗可改备注、重贴 cookie、密码重登 |
| cookie 快照 | 启动时给无 cookie 文件的 ego 账号补一份（趁浏览器还是它自己的会话） |

### 顺带修的

- 放开「ego 只能 1 个账号」的限制（现在按 cookie 切换，可多账号）。
- 任务去重：上游 id 全局唯一 → `taskKey` 改用 upstreamId，启动时按 upstreamId 合并重复行（之前不同账号槽位会写重复）。
- 删除的账号不允许再导入 cookie（`status=removed` 直接拒）。

### 上游关键事实（实测，详见 .analysis/REA-VEDA.md）

1. **免账号**：身份 = 服务端下发 `veda_did`（UUID.签名段，别自造）+ `X-Device-Id` 头；落 `data/veda.device.json`（0600，已从 git 移除）。
2. **额度按出口 IP 计，不是按设备**：4 组完全不同设备身份 → `/api/quota` 的 used/window_start 完全一致；`scope:"device"` 是误导字段名。
   用户问的「伪 IP 绕过」：自造 XFF 无效（Cloudflare 只信 CF-Connecting-IP）；换真实出口 IP 技术上可行但属刷免费研究资源，**明确不做**（政策选择不是技术限制）。

4. **写通道不需要浏览器**：不带 `X-Fp` 直接 POST → 201。与 Paba（TLS 指纹 + Turnstile 强制浏览器）根本不同。
5. **产物公开可下**：`/api/jobs/{id}/video` 无 Cookie、支持 Range（206）。
6. **无任务列表接口**：`GET /api/jobs` → 404，只能前进式同步，job_id 必须本地落库。
7. **字段坑**：`created_at` 是 ISO 字符串（按秒级 *1000 会 NaN）；进度全嵌在 `progress` 里；排队时长在 `timings.queue`。
8. **实测耗时**：5s/9:16 = 排队 181s + 生成 162s ≈ 5 分 44 秒；额度 20 credits/天（5s=1/10s=2/15s=3）+ 同网络 30 条/天。
9. **网络抖动**：偶发 `UND_ERR_CONNECT_TIMEOUT`（同域不同 CF 节点）→ GET 加 3 次退避重试；**POST 不重试**（防重复扣费）。

### 关键设计决定

1. **MCP 层是薄壳**：业务规则（额度闸/prompt 规范化/队列/镜像）全在 daemon，
   MCP 侧只做参数整形与结果压缩 —— 避免两份实现漂移。
2. **daemon 按需自动拉起**（关键）：本机 `launchctl bootstrap` 与 `crontab` **都被沙箱禁用**
   （连最小 plist 都是 `Input/output error`），做不了开机自启。
   所以把「起服务」下沉到适配层：agent 首次调工具 → 发现 daemon 没跑 → spawn + 轮询探测（≤15s）→ 端口占用则复用。
   **换电脑因此零配置，不需要任何系统权限。**
3. **错误可执行**：每个错误码带 `next` 字段，告诉 agent 下一步做什么（等额度 / 换上游 / 触发验证）。
